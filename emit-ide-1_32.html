EMIT

A typed language that compiles to real WebAssembly in your browser. Write code, hit ▶, runs instantly. No install, no server, one HTML file.

Types

int — 64-bit integers. Write 42.

num — 64-bit floats. Write 3.14.

str — strings. Write "hello".

bool — true / false. void — no return.

arr / numarr — an Emit array of whole numbers / of nums: let xs = [1, 2, 3], newArray(n). See Array Literals.

js — any JavaScript value (object, array, string, number, null…). You get one from obj.prop, obj.method(), new X(), a[i]. See The js type below.

Syntax

let x = 10 — immutable variable

mut y = 0 — mutable variable (top-level becomes a global, persisting between calls)

A top-level variable must start with a literal (0, 2.5, "text", true, null, 60 * 60); assign anything computed inside a function.

fn add(a: int, b: int) int { return a + b } — function

export fn run() { } — exported to JS, called by Run button

if (x > 0) { } else { } — conditionals

while (cond) { } — loops

for (let i = 0; i < 10; i++) { } — C-style for

break / continue — leave the loop / go to its next round (in a for the update still runs)

let r = await promise — wait for a promise. try { } catch (e) { } finally { }, throw "message" — errors. See await and try / catch below.

Array Literals

let nums = [1, 2, 3, 4] — int array

let xs = [1.5, 2.5, 3.5] — num array (float-typed by inference)

let words = ["red", "blue", "green"] — string array

An array literal (and newArray(n)) has type arr; with a decimal in it, numarr.

nums[i], nums[i] = v, nums[i] += 1, nums.length, nums.push(v), nums.pop() — an arr element is an int, a numarr element a num. Reading past the end gives 0.

for (let i = 0; i < nums.length; i++) { print(nums[i]) }

fn total(xs: arr) int { }, fn make() arr { return [1, 2] }, let fs: numarr = newArray(8) — as a parameter, return or variable type. arr, numarr and int can be assigned to each other (older programs keep an array in an int); [ ] and .length need the variable to be an arr / numarr.

Handed to JavaScript an Emit array becomes a real JS array (a copy): JSON.stringify(nums), "nums: " + nums, obj.list = nums, lib.draw(nums), let j: js = nums, nums.join("-"), nums.map(fnRef(f)). String literals in it arrive as strings. Changes JS makes to the copy do not come back.

The array builtins still work, also on an array kept in an int: arrayLen(nums), getItem(nums, i), setItem(nums, i, v), getNumItem, setNumItem, push, pop, toJsArray(nums).

JS Library Interop — Path C

Type use libname at the top to load a library from CDN. Then call its globals as if they were Emit functions:

use confetti

confetti() — calls window.confetti directly

Not in the list? use loads any browser library:

use tinycolor2@1.6.0 — any npm package (via jsDelivr), then call its global

use "https://example.com/lib.js" — any script URL (quotes optional)

use "https://example.com/lib.css" — a URL (or npm path) ending in .css loads a stylesheet instead of a script. Libraries from the list bring their own stylesheet (leaflet, flatpickr, swiper, notyf, nprogress), so use leaflet is enough. If a stylesheet cannot be loaded the program still runs and the output shows one amber ⚠ line.

use nanoid as Nano — ES module: its exports become Nano.someFn(). Works with URLs too. An npm name is imported from jsDelivr (/+esm); if that fails to load or throws, the IDE tries https://esm.sh/<name> once before reporting an error (the message names both). To pick the source yourself: use esm.sh:nanoid as Nano or use jsdelivr:nanoid as Nano.

Offline cache: where the browser gives this page storage, the text of every script and stylesheet that has loaded is kept. Libraries always load from the network first; only when that fails (no connection) is the stored copy used, and the output says so with an amber ⚠ line. The 📚 panel shows the size of the cache and a Clear button. ES-module libraries (as Name) are not cached. Opened from a phone's local storage the page may have no storage at all — then nothing is cached and everything works as before; use Export .html (offline) to get a program that runs without a network.

For library namespaces, use member access:

use babylon.js

let s = BABYLON.Scene(engine)

s.render()

Every obj.method(args) dispatches to the real JS object via the runtime handle table. Return values come back as handles you can chain off of.

Building JS Config Objects

Many JS libraries take an options object. Write it as an object literal:

confetti({particleCount: 100, spread: 90, colors: ["#f00", "#0f0"], origin: {y: 0.6}})

let opts = {title: "Hi", "quoted key": true, 3: 1.5, list: [1, 2],} — keys are words, strings or numbers; values are any expression; nesting and a trailing comma are fine. The result is a js value. A { at the start of a statement is still a block.

Array literals handed to JS are JS arrays: JSON.stringify([1, "two", [3]]), obj.list = [1, 2], arr[0] = ["a"], let a: js = [1, 2, 3], new Map([["k", 1]]). A literal written right there is built as a JS array directly; let xs = [1, 2, 3] is an Emit array (arr), which is converted to a JS array when it is handed to JS.

The older way still works — emptyObj() + field assignment:

let opts = emptyObj()

opts.particleCount = 100

opts.spread = 90

confetti(opts)

Nest objects by assigning one to a field of another. Numeric property names work too: opts.0 = "star" for array-like config.

Interop Builtins

emptyObj() → js — returns a handle to a fresh JS {}
__jsGlobal("name") → js — handle to window.name (e.g. for confetti.shapeFromText)
toStr(handle) → str — convert a JS value handle to an Emit string
toNum(handle) → num — convert a JS value handle to an Emit number
toJsArray(emitArr) → js — convert an Emit array to a real JS Array (handle)
wrapShape(s) → int — wraps a single shape into {0: s, length: 1} (legacy helper)
getCanvas() → js — handle to the current canvas, for libs that need a canvas element
toInt(handle) → int — convert a JS number handle to an Emit int (e.g. toInt(arr.length))
jsLen(handle) → int — .length (or .size) of a JS array, string, Map or Set
jsAt(handle, i) → js — element i of a JS array (same as arr[i])
jsGet(handle, key: str) → js — obj[key], for keys only known at run time (same as obj[key])
jsKeys(handle) → js — handle to the JS array Object.keys(obj)

The js type

A value that lives on the JavaScript side has type js. let o = lib.thing infers it; you can also write it: fn onHit(other: js), let o: js = null, mut player: js = null. (Older programs declare such values as int; that still works, and int and js can be assigned to each other.)

It converts itself where a type is needed.

let c = obj.count   print(c + 1)   if (obj.count > 5) { } — arithmetic and comparisons use the number. With an int operand the result is an int (obj.size * 2 drops the fraction; write obj.size * 2.0 for a num).

let v = o.visible   if (v) { }   if (!v && o.ready) { } — conditions use JS truthiness.

let s: str = obj.name, let n: num = obj.x, let i: int = obj.count, printStr(obj.name), return obj.x — declared types convert.

if (a == null) { } null check · if (a == b) { } same JS value · if (obj.name == "bob") { } string equality.

Passed to a JS call it is the value itself, and a js variable holding null arrives as null.

Global JS functions. Any name that is not an Emit function or builtin is called as window.name(args): parseInt("12"), dayjs(), dayjs("2024-03-15"), numeral(1234.5). Each call may pass different arguments (numbers, strings, true/false, null, js values) and the result is always a js value.

Calling a function value. A js variable or any expression can be called: let f = d3.format(".2f")   f(3.14159), d3.format(",")(1234), fns[0](x), fn apply(cb: js) { cb(1) }. A name that is an Emit function or a builtin always means that function.

String +. + with a string on either side concatenates; the other side may be a str, js, int, num or bool: "name: " + obj.name, "n=" + count, s += "!". Numbers are written as JS writes them ("x" + 3.0 is x3, unlike numToStr(3.0) = 3.0); a null js value adds nothing.

Index. let x = arr[i], arr[i] = v, obj["key"] = v, grid[y][x] — on js values, strings and Emit arrays (arr / numarr: xs[i] is an int / a num).

String methods. Emit strings accept JS methods: "a,b".split(","), s.toUpperCase(), s.length, s[0]; numbers too: x.toFixed(2). The result is a js value.

Callbacks, Promises, Null

Callbacks. fnRef(myFn) turns an Emit function into a JS function a library can call. JS arguments are converted by the parameter types you declare: int / num take numbers, str takes a string, bool takes true/false, and a js parameter takes anything (objects, events, values of unknown type). The return value goes back to JS the same way.

fn visit(value: num, index: int) { printNum(value) }

arr.forEach(fnRef(visit))

el.addEventListener("click", fnRef(onClick)) — fn onClick(ev: js) gets the event object

setTimeout(fnRef(tick), 100)

Promises. Use await (next section), or pass callbacks — the resolved value arrives with the type you declare.

fn onDone(result: js) { printStr(result.title) }

fn onErr(err: js) { printStr(err.message) }

lib.load("x").then(fnRef(onDone)).catch(fnRef(onErr))

A rejected promise with no .catch shows a red ✗ unhandled promise rejection: message line in the output.

Null. JS null and undefined both come back as handle 0: if (isNull(el)) { } or if (el == null) { }. typeOf(h) gives "object", "array", "string", "number", "boolean", "function" or "null".

Constructors. let d = new Date(2024, 0, 15), let v = new BABYLON.Vector3(0.0, 1.0, 0.0). Write new when you mean it. A call without new is a plain function call — Math.max(1, 2), String(5), Phaser.Math.Distance.Between(0.0, 0.0, 3.0, 4.0) — unless the function is recognisably a constructor, in which case it is constructed for you (THREE.Scene(), Date(2024, 0, 15)): it is written with class, or its prototype has members of its own or inherits from another class, or its name is capitalised and its body assigns to this. A plain call that fails with “cannot be invoked without 'new'” is retried with new.

Typed values from JS. See The js type above: let s: str = obj.name, if (obj.visible) { }, obj.count + 1. toStr / toNum / toInt convert explicitly.

Loops over JS arrays. for (let i = 0; i < jsLen(arr); i++) { let item = arr[i] }

Errors. If a JS call throws, a red ✗ jsCall .method(): message line appears in the output, the call returns null (0) and the program carries on — unless the call is inside a try block (see try / catch).

await

let r = await fetch(url)   let t: str = await r.text()   await sleep(500)

await x waits for the promise x and gives its resolved value (type js; it converts like any JS value). A value that is not a promise is returned as it is. sleep(ms) returns a promise that resolves after ms milliseconds.

for (let i = 0; i < 100; i++) { draw(i)   await sleep(16) } — a loop that lets the page breathe; buttons, timers and callbacks keep working while it waits.

A function that uses await (or calls an Emit function that does) is async: called from Emit it simply waits; started from the outside — Run, frame(), onclick_N, ontimer_N, a fnRef callback — it runs in the background and JS gets a promise (fnRef(loadIt) behaves like a JS async function). frame() is not called again while the previous frame is still waiting. Run does not wait for it, and Stop or running again abandons calls that are waiting.

A rejected promise is an error like a call that throws: inside try it goes to the catch, otherwise a red ✗ await: message line appears and await gives null.

await needs a browser with WebAssembly JSPI (Chrome / Edge 137 or newer at the time of writing). Elsewhere a program that uses it stops with “This browser does not support await” — use promise.then(fnRef(callback)) there. Programs without await are not affected.

try / catch

try { let cfg = JSON.parse(text)   use(cfg) } catch (e) { printStr("bad input: " + e.message) }

Inside try, anything that fails on the JS side — a method or function that throws, new, reading or setting a property of null, an awaited promise that rejects — jumps to the catch block instead of printing the red line. Also from inside Emit functions called in the try, and from fnRef callbacks that JS calls during it (try { list.forEach(fnRef(visit)) }): they return at once and the caller's catch runs. (An async callback is its own call: it gives JS a promise, and what it does not catch itself is reported.)

e is the thrown JS value (type js): e.message, e.name. A thrown text or number is wrapped in an Error, so e.message always works.

throw "something is wrong" raises an Error with that message; throw e passes a caught error on. Not caught by any try, it ends the running call and shows as a red ✗ line.

try { } finally { } / try { } catch (e) { } finally { } — the finally block runs afterwards in every case: normal end, caught error, an error that goes on to an outer try, and return / break / continue out of the block. (Only a WebAssembly trap — an integer division by zero, endless recursion — skips it.)

Outside try nothing changes: a failing JS call prints its red line, returns null and the program carries on.

Modules

A project can be several files. One file = one module, named after its path: game/physics.emit is module game.physics, main.emit is module main. All files are compiled together into one WebAssembly program (so modules may import each other in a circle).

public fn step(dt: num) num { }   public let gravity = 9.8   public mut ticks = 0 — visible to other files. Everything else is private to its file: two files can each have their own count or helper(). export fn is public too.

import game.physics — then physics.step(1.0), physics.gravity, physics.ticks = 0, fnRef(physics.onHit) (the last part of the module name is the prefix)

import game.physics as p — then p.step(1.0)

import game.physics.step — then step(1.0) directly; import game.physics.step as advance renames it

import game.physics.* — every public name of the module directly. If two star imports offer the same name, using it is an error (import the one you mean by name); a name of the file itself or one imported by name always wins.

Imports go at the top level of a file, anywhere before or between the other declarations. A local variable or parameter called like an import prefix hides it inside that function (the compiler warns). let variables of another module can be read but not assigned; declare them public mut for that.

package game — optional first line, as in Java. It must match the folder of the file (game/physics.emit → package game; a file in the root has none). The path is what counts.

The entry file is the first file of the project. Its export fns keep their plain names (run, frame, onclick_1 …) and are the ones the page calls. An export fn step in another module is exported to JS as game.physics.step; frame / onclick_N / ontimer_N / onhttp_N only work in the entry file.

Builtins, JS interop, use lines, await and try work the same in every file. import fn name(x: int) from "env" is still a raw WebAssembly import (see Custom Imports) — the fn makes the difference.

One text. A whole project can be written as one text: a line //// file: game/physics.emit starts a new file (paths are relative, use /, and end in .emit); the text before the first such line is main.emit. In a project with several files, errors are shown as path:line:col: message.

import game.physics
import game.physics.gravity

export fn run() {
  printNum(physics.step(0.5) + gravity)
}
//// file: game/physics.emit
package game

public let gravity = 9.8
mut calls = 0            // private

public fn step(dt: num) num {
  calls++
  return gravity * dt
}

Memory: regions and structs

A region is a fixed block of WebAssembly memory with a name, an element type and a length. Reading and writing it compiles to single load / store instructions — no call into JavaScript per access — so it is the fast way to keep big tables, particles, grids and pixel buffers. It is raw memory without C’s traps: there are no pointers and no pointer arithmetic, every index is checked, memory starts zeroed, a region can be locked read-only, and the IDE can show what is in it.

struct Ball { x: num, y: num, r: int, alive: bool }   region balls: Ball[100]   region fb: u8[320 * 200 * 4]   region grid: int[64] — at the top level of a file; public struct / public region make them visible to other modules (physics.balls[i].x, import game.physics.Ball). The size is a constant: int literals with + - * / % and parentheses.

Element types: i8 u8 i16 u16 i32 u32, int (64-bit), f32, num (64-bit float), bool (1 byte) and structs. Reading a narrow integer gives an int (sign- or zero-extended); storing one keeps the low bits — it wraps the way the machine does (u8: 300 → 44, i8: 200 → -56). f32 reads as a num; a store rounds to float precision. Storing a num into an integer element, or a number into a bool, is a compile error (round with floor() / round(), or write a comparison).

Structs hold fields of those types, other structs by value (pos: Vec → balls[i].pos.x) and fixed arrays of numbers (hist: i16[3] → balls[i].hist[2]). The compiler lays them out: fields in order, each at its natural alignment, the size rounded up to the largest alignment. There are no casts and no way to read the bytes as another type. A field cannot be str, js or arr: the memory manager does not look inside regions, so a string or JS value kept there could be released while still in use (keep an index into an arr instead). Arrays of structs inside a struct are not supported yet.

grid[3] = 5   grid[i] += 1   grid[i]++   balls[i].x = balls[i].x + 1.5   balls[i].pos.y -= 1.0   balls[j] = balls[i] (copies the whole element)   grid.length (the element count, a constant)

with names one element for a block without copying it: with balls[i] as b { b.x += b.vx   b.y += b.vy }. The index is evaluated and checked once; inside the block b.x is a direct load / store. b is not a value: it cannot be stored in a variable, returned, passed to a function or pointed at another element, and it does not exist after the block. balls[k] = b copies the element.

Regions as parameters: fn sum(r: region int) int { let s = 0   for (let i = 0; i < r.length; i++) { s += r[i] }   return s }, then sum(grid); fn step(bs: region Ball). The function works on the caller’s region itself (nothing is copied); r.length is that region’s length and every index is checked against it. A region cannot be put in a variable, returned or stored — it is not a pointer — and an export fn or a fnRef callback cannot take one (JavaScript has no region to pass).

Whole-region operations: fill(grid, 7)   wipe(grid) (all bytes zero; also for struct regions)   copy(src, dst)   swap(a, b) — copy and swap need the same element type and length (a compile error when both are known, a run-time error through a region parameter).

Bounds. Every [i] is checked: 0 <= i < length. A constant index is checked by the compiler instead (grid[64] on a 64-element region does not compile) and costs nothing when the program runs. A failing check stops the current call with a red line such as ✗ run → grid[70]: index out of range (length 64) at main.emit:12:5. Inside try it is caught like any other error (e.message is that text); in frame() each different message is shown once and the next frame runs normally. The check is one compare and a branch that is never taken: summing a region costs about 5% more than without checks, a byte-by-byte pixel loop up to about 25% (measured with tests/bench-regions.js) — and a region is still 40–70 times faster than an arr and thousands of times faster than JS objects reached through js values.

freeze. freeze(grid) makes every write from Emit code fail with ✗ write to frozen region grid at main.emit:9:3 (catchable the same way), including fill, wipe, copy into it and swap; thaw(grid) allows writes again; frozen(grid) tells which. Reads are never affected; the cost is one byte loaded and tested before each store. Writes from JavaScript through a view are not checked, and the IDE’s Memory panel may edit a frozen region on purpose.

Views for JavaScript. view(grid) is a typed array over the region’s bytes, without copying: Int8Array / Uint8Array / Int16Array / Uint16Array / Int32Array / Uint32Array / BigInt64Array (int) / Float32Array / Float64Array / Uint8Array (bool, and the raw bytes of a struct region). A region passed straight to a JS function arrives as such a view: console.log(grid), chart.plot(samples); view(grid) gives you one as a js value. Memory can grow while a program runs (strings are allocated in it), and growing makes every earlier typed array over it empty (length 0). view(r) always returns one that is valid at the time of the call — ask for it again instead of keeping one in JavaScript across calls that may allocate.

A memory-mapped screen. screen(fb, 320, 200) or screen(fb, 160, 100, 3) (each pixel 3×3, sharp): fb must be a u8 region of at least width × height × 4 bytes, red / green / blue / alpha per pixel, row by row. It adds a canvas to the output (like canvas()) that shows the region and is redrawn every animation frame while the program runs, and right after every call from the runtime (Run, frame(), buttons, timers), so a picture drawn once appears too. Write pixels with fb[(y * 320 + x) * 4] = 255; set alpha to 255 to see them. touchX() / touchY() are page coordinates, as with canvas(): subtract the canvas position and divide by the scale to get a pixel.

Layout and limits. Regions live in memory from 64 KB up, in declaration order, followed by a small table (address, length, frozen flag per region); strings start after them. All regions of a program together are limited to 256 MB. Memory starts zeroed and every Run starts from fresh memory. Not supported yet: regions sized while the program runs (and released automatically), str / js / arr fields, arrays of structs inside structs, slices or views of part of a region, regions in the wasm64 target.

Projects and files

A program can be one file or several. File → New file in project… adds a file; from then on a strip of tabs sits above the editor, one per file, with + at its end. A program of one file looks and works as before, without tabs.

Tabs. Tap a tab to open that file. ⋯ on the open tab — or a long press (right click) on any tab — offers Rename, Make entry file and Delete. With a keyboard: Ctrl+PageUp / Ctrl+PageDown or Alt+← / Alt+→. Every file keeps its own cursor, scroll position and undo history (Ctrl+Z, Ctrl+Shift+Z, or ↶ ↷ at the end of the key bar); the undo history is not saved.

Entry file. The first tab, marked ▶, is where the program starts. It cannot be deleted while there are other files: make another file the entry first. A file name is a path such as physics.emit or game/physics.emit — letters, digits, _ - . and / for folders, ending in .emit. The path is also the file’s module name: game/physics.emit is game.physics. The Modules example is a small project of three files.

Run compiles all files together. In a project of several files an error reads game/physics.emit:12:3: message; tap it to open that file at the line. The tab of a file with errors is marked red until a Run finds none in it. use lines work in any file; the 📚 panel adds them to the entry file.

Autocomplete. After import the editor suggests the project’s modules, and after import game.physics. that module’s public names and *. After an imported module’s name and a dot (physics.) it lists the public functions with their parameters, and the public variables. Names imported directly or with * join the ordinary suggestions.

Find. File → Find / replace… (Ctrl+F, Ctrl+H) opens a bar above the editor: ↑ ↓ go to the previous / next match (case matters). all files lists every matching line of the project as path:line: text — tap one to open it — and lets ↓ continue into the next file. All replaces every match in the open file; in all files mode it replaces in every file, after asking.

Saving, sharing, opening. Save .emit, the share link and the autosave each hold the whole project as one text: the entry file first, then every other file after a line //// file: game/physics.emit. A program of one file has no such line, so its .emit is just its source. Do not type such a line into a file: the next Run would turn the text below it into a tab of its own (and says so). Open .emit accepts several files at once: a file that contains //// file: lines is a whole project and replaces the current one (only one such file at a time); plain files become files of the project, named after the files you picked — you are asked whether to add them or to replace the project.

Scripts. Code that sets the editor’s text and fires an input event replaces the open file — or, when the text contains //// file: lines, the whole project.

Memory tab

Output → Memory is a front panel for the program’s memory regions (region grid: int[64], region balls: Ball[100]): one card per region, in the order they are declared. A dot on the tab means the program has regions; without any, the tab explains how to declare one.

Cards. The header shows the name (and the module, for a region of another file), the element type and length, the size in bytes and the base address. Tap it to open or close the card; regions of up to 64 cells start open. A region of numbers is a grid of cells, the index above each value. A struct region is a table, one row per element and one column per field (nested fields as pos.x); swipe it sideways. Big regions show one page at a time: ⇤ ‹ › ⇥ and go to #.

Display. dec / hex for whole numbers; a u8 region also has ascii, dump (offset, 16 bytes and their characters; tap a row to edit those bytes) and pixels (the bytes as RGBA pixels at the width you type — a framebuffer drawn with screen, say).

Live. While the program runs and the tab is open, the visible cells are read again about six times a second and a cell that changed flashes. When nothing runs, the tab is read when you open it and after each poke. A closed tab costs nothing.

Poke. Tap a cell, type, Enter (Escape cancels): 42, -7, 0x1f, 'A', 2.5; 64-bit values in full. A bool cell toggles on a tap. Input that does not fit the type writes nothing and says why. Pokes work while the program runs, after Stop and after it ended.

Lock. 🔓 / 🔒 freezes or thaws a region, like freeze(r) / thaw(r): a write by the program to a frozen region stops it with a red error. A poke is a front panel write: it overrides the lock. A red runtime error that ends in at path:line:col is a link: tap it to see the place in the editor.

Custom Imports

For full control, declare imports explicitly:

import fn fetchAPI(url: str) from "http"

Then provide the JS implementation when instantiating the exported WASM.

How It Works

Emit compiles to real WebAssembly bytecode in your browser. Pipeline: lexer → parser → type annotator → type checker → WASM binary emitter. int = i64, num = f64. Strings stored in linear memory with length prefix.

JS interop uses a runtime handle table: every JS object you reference gets an integer handle. Member calls dispatch through __jsCall, global-function calls through __jsCallG, calls of function values through __jsCallV, property access through __jsGet, field assignment through __jsSet. Args and field values are marshalled through a tagged buffer at offset 48640.

Export

Use the File dropdown to download your program:

.html — one standalone page that runs your program the way Run does, without the editor. It contains the compiled WASM, the list of imports it needs and the Emit runtime itself (the same code this IDE runs programs on: print, canvas, buttons, inputs, sound, strings, JS interop, callbacks, animate(), keyboard and touch). On opening it loads the libraries from your use lines from their URLs (so those need a network connection; a library that fails to load is reported on the page), then calls every exported function that takes no parameters. Functions with parameters are not called automatically, and the IDE's call-trace lines are hidden and printed lines appear without the IDE's > prefix (add ?trace to the address to see the page exactly as the IDE's output, trace lines and prefix included). About 90 KB plus your program.

.html (offline) — the same page with every library embedded: the scripts, the scripts they need, their stylesheets (images and fonts under 200 KB that a stylesheet refers to are inlined; larger or unreachable ones stay network links and are listed after the export) and ES-module libraries together with the modules they import. The file needs no network at all and is as large as its libraries (three.js about 0.6 MB, Babylon about 9 MB). The libraries are downloaded while exporting, so that step needs a connection; if one cannot be downloaded (no network, or a server that does not allow it) the export stops with a message and no file is written — use the normal .html export then. ES modules that import each other in a cycle cannot be embedded. Things a library fetches by itself while running (map tiles, models, fonts by URL) still need a network. .js (offline) is the same for the module export.

.js — the same contents as an ES module for a web page of your own: import init from "./program.js", then const app = await init({target: someElement}). init loads the libraries, starts the program like the .html export and returns app.exports (your exported functions; int values are BigInt). Output goes into the element with id tab-output, created inside target if the page has none. Browser only, one Emit program per page. The comment at the top of the file describes the options.

.wasm — the raw WebAssembly module only, with no runtime. It runs anywhere WebAssembly does (browsers, Node.js, Deno, Wasmtime), but the host must supply every import itself: the std builtins the program uses (int = i64/BigInt, num = f64, strings = pointer to a 4-byte length followed by UTF-8 in the exported memory), the __js__ interop functions and, if the program uses fnRef, a function table as __cb__.table. A program that only computes and returns numbers needs none of this; for anything else the .js export is the practical choice — its header lists the imports.

.emit — save your source code: every file of the project in one text file (see Projects and files).
